# 安卓通用性与使用体验审查

日期：2026-10-11。

结论：目前是可继续增量开发的通用基础，适合开发者试用；尚不足以作为普通用户省心使用的通用手机助手。

## 通用性

| 项目 | 当前实现与证据 | 判断 |
|---|---|---|
| 应用发现、语义点击、文本输入、页面读取 | 同一套工具已在时钟、设置模拟器任务通过 | 有通用基础，不能推导任意 App 可用 |
| 滚动、滑动、长按、返回 | 已实现；本轮未建立第三方 App 实测基线 | 需要按能力验证迁移 |
| 键盘搜索/提交 | 尚无明确的 submit/IME 动作契约 | 常见搜索流程存在缺口，下一增量优先研究 |
| 动态加载与阻塞恢复 | 固定动作后延迟、观察重试与步骤上限；缺条件等待和用户处理后恢复流程 | 长流程还不稳定 |
| 视觉操作 | 截图传递有转换单测，缺视觉任务基线和坐标操作 | Canvas 等场景未覆盖 |
| 真机与后台 | 仍缺真机产品基线 | 模拟器不能替代验收 |

先选一个第三方 App 的只读搜索任务，围绕实际失败补提交、等待或选择能力；继续复用三个工具，不增加各 App 专用流程。

## 本轮改变

- REUSE：现有 Compose 页面、模型配置、三个工具与手机内 Agent loop。
- EXTEND：统一任务入口的权限/锁屏检查，模型错误中文提示，菜单中的新任务入口。
- REPLACE：默认展开的服务地址与模型名称、常驻诊断按钮、技术状态标签、没有实际连接测试的“保存并连接”文案。
- REPLACE：恢复用户看不到的旧模型历史；测试格式从旧消息猜测的行为。

默认模型设置只显示密钥输入，高级设置按需展开。已经配置密钥时，可以留空保存其他设置；取消不保留尚未保存的密钥。首次通知授权由用户点击开启，不在打开应用时立即弹出。

日常页面提供任务输入和一个可填入示例的按钮；设置和诊断藏在菜单。进度使用“正在填写内容”等中文描述，仅显示当前步骤，避免每个工具调用都刷一条聊天消息。错误说明处理办法，不直接显示 provider 错误原文；执行返回结果不一律宣称目标已完成。

所有任务入口检查模型密钥、无障碍、通知及屏幕状态。通知检查同时包括任务和确认通知渠道。前台服务启动失败会给出处理提示；任务输入仅在请求被接受后清空。

## 修复一个影响日常使用的问题

原先冷启动后聊天界面为空，模型仍恢复旧 SharedPreferences 中的历史；模型客户端又扫描历史用户消息来决定 benchmark 输出格式。实际从页面发出的普通任务因此被旧 `[BENCH:L1]` 影响，仅返回计划 JSON，工具调用为零。

现在 Android 模型上下文跟随当前可见对话，不静默加载旧历史。当前进程内仍支持连续对话，“新任务”清空当前对话上下文，不清除模型凭据或历史 benchmark 记录；冷启动开启新对话，不自动恢复旧任务。已有序列化记录保留，未增加自动重放。

benchmark_task_id 由本次 prompt 显式确定，经 Native bridge 传给模型客户端。普通任务为 null，旧历史和截图消息不能改变当前格式。QuickJS 与 WebView carrier 使用同一边界。

## 验证

- TypeScript check、Android debug APK 构建通过；Node 测试 56/56，Android JVM 测试 50/50。
- 模拟器页面实际检查了默认收起高级设置、空密钥保存后仍可使用原有在线模型、新任务与示例填入。
- 直接从实际页面执行“新任务 → 示例 → 发送”：observe 1、invoke 1、click 2，耗时 29.672 秒；独立观察确认最终选中 Alarm，返回页面显示中文结果与页面核对说明。[原始记录](results/android-ux-ui-task-2026-10-11.json)
- 修改前的失败是普通任务没有工具调用、返回计划 JSON；记录未算作通过。[修改前记录](results/android-ux-ui-task-before-2026-10-11.json)
- 关闭通知权限后，从 debug 入口发任务：没有创建运行记录，界面显示中文通知开启提示。测试中权限撤销/强制停止清掉了无障碍开关，测试后按原配置恢复；不算作产品具有自动恢复权限的能力。
- 原有 `[BENCH:L1]` 模拟器 smoke 仍通过，耗时 12.875 秒；本轮只验证模拟器。

本轮没有清除旧应用数据或更换原有模型密钥；没有做全新安装、首次填入新密钥、真实用户测试、真机或 APK 正式分发验收。普通用户仍需自行取得模型密钥、处理系统授权；这两项安装与账户门槛不能靠简化页面就视为解决。

下一步应围绕一个真实 App 的只读搜索流程补通用能力，再验证新用户从安装到完成首个任务的完整过程。
