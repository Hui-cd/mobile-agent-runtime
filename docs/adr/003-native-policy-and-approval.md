# ADR-003：风险策略和用户确认属于原生安全边界

> 状态：Accepted
> 日期：2026-09-04

## 背景

模型输出和目标页面内容都不是可信输入。发送、删除、购买、支付、拨号和分享等动作可能产生真实外部影响，不能依赖模型自行决定是否确认。

## 决定

风险判断、用户确认、设备权限和密钥留在 Kotlin 原生层，不放入 Pi/QuickJS。

执行顺序固定为：

```text
Tool Call
  → 参数校验
  → Policy 计算风险
  → 必要时暂停并请求用户确认
  → Android Runtime 执行
  → Observation / ToolResult
```

确认请求必须包含结构化的：

- `action`：将执行什么；
- `target`：对谁或对什么执行；
- `effect`：可能产生什么后果；
- `riskLevel`：风险等级；
- `toolCallId`：确认只对当前调用有效。

拒绝返回明确的 `USER_DENIED`，不得静默改写为允许，也不得自动重复弹出同一确认。

## 结果

- 即使模型或页面文本被误导，关键动作仍经过可信边界；
- UI 可以准确说明确认对象和后果；
- 审批记录可以与具体 Tool Call 和执行结果关联；
- Policy 需要独立演进和测试，不能长期依赖按钮文字关键词。

## 当前差距

当前实现使用描述字符串和关键词识别风险，只是原型级策略。生产收口需要结构化动作语义、风险矩阵、调用级审批记录，以及“动作已执行但结果未知”的恢复规则。
